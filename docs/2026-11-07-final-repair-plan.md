# DJ 4G Hub 最终修复计划与实施步骤

日期：2026-11-07

状态：部分实施；通知、任务、状态展示、扫描触发、基础来源保护和提醒协同等已优化，见 [本轮实施与验证记录](2026-11-07-feature-optimization-and-verification.md)。完整认证、USB 生命周期/AT 事务及真实业务验收仍未完成，不能将整份计划标为完成。
依据：[原问题清单](2026-11-07-project-issue-review.md)、[独立评审](2026-11-07-repair-plan-assessment.md)、[功能梳理报告](2026-11-07-feature-audit.md)。

## 1. 目标与执行原则

本计划替代原问题清单中的“四批修复顺序”，作为后续执行依据。保留原文问题编号以便追踪，采用评审后的修复方法。

交付目标：

1. 保护通知凭证和本地控制接口，通知失败不能拖垮 HTTP、SIP 或电话服务。
2. 解决 USB 生命周期及 AT 事务竞争，控制扫描对来电、接听、挂断的影响。
3. 统一本地与上游的电话控制、音频和提醒，保留已验证的双向语音能力。
4. 完成任务恢复、后台退出和状态显示修复，形成可重复的构建、测试与功能验收记录。

执行原则：

- 先保存完整工作快照，再做业务修改；紧急局部修复不依赖完成上游整合。
- 每个高风险改动同步增加针对性测试，验证通过后进入下一依赖步骤。
- “实现存在”“自动测试通过”“实机读取正常”“业务闭环通过”分别记录。
- 本计划不把文档中描述的目标写成已验证结果；不根据 HTTP 200 或收到音频数据判断功能完整。
- 发布前保留旧版本及兼容配置的恢复路径，不覆盖用户其他改动。

## 2. 执行路线

| 阶段 | 步骤 | 核心产出 | 进入下一阶段的条件 |
| --- | --- | --- | --- |
| 0：保全 | 01–02 | 可恢复工作快照、测试基线和通话测量口径 | 源码完整、基线可定位 |
| 1：安全与稳定 | 03–05 | 安全错误、SMTP 故障处理、API 访问控制 | 故障不崩溃，凭证不回显，合法客户端可用 |
| 2：设备与响应 | 06–07 | USB 生命周期管理、AT 事务边界、显式扫描 | 并发用例通过，电话控制不被新增锁长期阻塞 |
| 3：电话整合 | 08–09 | 单一控制链、统一提醒、可比较的语音结果 | 接听/挂断闭环及双向语音通过 |
| 4：业务可靠性 | 10–11 | 可取消后台任务、恢复语义、准确状态 | 退出和故障恢复用例通过 |

## 3. 逐步实施

### 步骤 01：保存工作区，确定修复基线

对应：A1、A2、A3、A5。

1. 记录当前分支、HEAD、工作区改动、未跟踪源码及本地上游引用；需要比较新上游时先更新引用并记录时间。
2. 显式选取源码、文档和必要资源形成可恢复快照；检查凭证、构建产物和个人文件，不使用未经检查的全部暂存。
3. 保留未跟踪源码；单独保存补丁不足以备份全部新功能。记录快照的恢复方式并验证文件清单。
4. 为修复使用独立分支；快照若暂不具备可独立构建的提交边界，明确标记，后续再整理。
5. 为源码目录中的二进制增加精确忽略规则；确认用途和可重建性后再清理。个人启动文件决定保留本地或整理入发行目录。

**验收**：快照覆盖本地新增功能；无真实凭证或无关生成物被误纳入；恢复说明可执行。

### 步骤 02：建立自动测试和电话体验基线

对应：Q3，以及通话质量的验收缺口。

1. 记录系统架构、Go/cgo、libusb、模块固件、音频输入输出及当前测试命令。
2. 运行普通测试、静态检查、前端语法检查；另行运行受支持平台上的竞争检测与无 cgo 构建，分别记录成功和失败。
3. 将普通自动测试与显式启用的硬件测试区分开，默认测试不拨号、不发短信、不重启设备。
4. 准备电话状态、USB、SMTP、HTTP 推送和持久化故障替身，以便后续修复在可控环境下验证。
5. 建立通话记录表：同一场景分别记录响铃、号码到达、点击接听、模块接通、首个有效声音、挂断和资源释放时间。

**验收**：失败项有可复现入口；历史报告的通过结果不冒充本轮结果；实机测量与自动测试分别存档。

### 步骤 03：统一通知错误输出与凭证处理

对应：S4、S7、S10；功能报告 F05。

主要范围：`cmd/dj4ghub-macos/notify_handlers.go`、`sip_handlers.go` 及相关测试。

1. 生成通道、阶段、错误类型、状态码等结构化安全错误，避免直接输出请求 URL、嵌套错误全文及第三方响应正文。
2. 覆盖 Telegram 轮询日志与发送结果记录两条路径；同时处理 Bark 路径中的密钥、标题和正文，以及其他通道的路径密钥和查询签名。
3. 在日志和 `recordNotifyResult` 入口增加兜底过滤。不得以 `URL.Redacted()` 作为路径密钥脱敏方案。
4. 取消 SIP 首启明文密码日志，保留安全的获取说明。
5. 确认码生成失败时返回错误，调用方停止确认流程，删除固定值回退。
6. 若确认历史日志含真实凭证，列出需轮换的凭证及日志副本范围；轮换后验证旧凭证失效，历史清理不损失必要故障记录。

**验收**：假密钥、假验证码在连接错误、超时、畸形地址和响应回显情况下均不会进入日志或 API；不读取真实秘密来证明脱敏。

### 步骤 04：修复 SMTP 故障与通知工作协程

对应：S5；功能报告 F04。

1. 检查 SSL 分支的 `smtp.NewClient` 返回值，失败时关闭连接，不使用空客户端。
2. 连接建立支持上下文；SMTP 欢迎语、TLS、认证、发送及退出均受连接期限约束，取消能终止阻塞。
3. 明确邮件配置中的传输策略：隐式 TLS、要求 STARTTLS、显式允许明文；要求 TLS 时不支持或握手失败即停止发送。旧配置迁移不得静默降级。
4. 在每个通知工作协程边界增加必要的 panic 兜底，记录安全错误，并保证计数和清理执行；正常错误检查仍是主要处理方式。
5. 保留 HTTP 推送已有的请求上下文期限，检查直接调用路径；不把 Bark 使用默认客户端误判为没有超时。

**验收**：模拟欢迎语错误、TLS 失败、断连、读写停滞和取消后，发送有界结束，HTTP/SIP 服务继续工作；各通道结果独立可见。

### 步骤 05：为本地接口建立统一访问控制

对应：S1、S2、S3、S8、S9。

主要范围：路由装配、JSON 解码、网页 API 客户端、MCP、SIP 设置及本地客户端。

1. 全部 HTTP 路径验证实际配置的 Host 与端口；如支持 IPv6，显式加入对应地址。不接受域名后缀匹配或未经信任的转发头。
2. 浏览器写请求执行严格 Origin 校验；Fetch Metadata 作为补充。JSON 写接口检查媒体类型，逐一兼容合法的非 JSON 入口。
3. 所有控制及敏感读取 API 要求身份凭据。浏览器采用受保护的本地配对流程换取会话；原生应用和命令行使用本地受限文件中的凭据。
4. 配对凭据由安全随机数生成，限时、一次性使用，通过本地启动器或受限文件提供；公开页面不内嵌长期秘密。配对接口同样校验 Host/Origin，禁止跨源响应开放。
5. 浏览器会话使用 HttpOnly、SameSite=Strict Cookie，并对写操作验证会话绑定的 CSRF 值；定义过期、退出和服务重启后的失效方式，避免在 URL 中长期携带凭据。
6. 保留 MCP 独立 Bearer 认证和只读范围，改为常数时间比较；原生应用及本地工具同步适配，不能用“没有 Origin”作为免认证理由。
7. SIP 默认回环；已配置局域网使用的场景须保留显式选项和访问限制。修改监听范围及凭据要求已认证配置请求，不为每次常规拨号弹额外确认。

**验收**：非法 Host、跨源读写、缺失/错误凭据及伪造写请求被拒；网页首屏、轮询、MCP、原生应用和命令行的合法流程通过。凭据交付与客户端适配必须和服务端防护一并交付。

### 步骤 06：修复 USB 生命周期竞争

对应：R1、R2 中的初始化问题。

主要范围：`main.go` 的 USB 打开、失效、重连和相关状态访问，`usbat_darwin.go`、SIP 音频适配。

1. 统一管理活动设备引用、连接代次、打开中状态、发现状态和退避；同一时间只允许一个打开过程。
2. 慢速打开在生命周期锁外执行，写回时检查代次；若结果已过期，关闭新开的过期句柄，不覆盖当前设备。
3. 调用方取得稳定设备引用及代次；只有对应连接的错误可以将它失效，旧请求不能清除新连接。
4. 失效时先在锁内摘除引用，再在锁外关闭或通知依赖组件；回调和初始化不持生命周期锁执行。
5. 明确与底层命令锁、eSIM 管理器及音频锁的顺序；避免回调重复加锁。短信重组器在受控初始化阶段构造。

**验收**：并发打开只产生一个有效设备；旧错误不清新设备；重复关闭及关闭后调用可控失败；重连后音频和 eSIM 引用不指向过期连接。替身测试实际触发这些路径并通过竞争检测。

### 步骤 07：建立 AT 事务边界并限制长扫描

对应：R2、R5、S6；功能报告 F01。

1. 为确实依赖共享状态的 SMS 等多命令序列增加事务边界；锁内使用不重复获取同一锁的执行入口。
2. 为事务设置期限和取消路径；接听、挂断等电话控制优先于尚未开始的后台查询。
3. 运营商 GET 仅返回缓存和扫描状态，POST 显式启动；网页打开和轮询不启动扫描。
4. 响铃或通话期间拒绝新长扫描并返回忙状态。对已开始扫描，只使用固件明确支持的中止方式；不能假定队列优先级会中断正在执行的硬件命令。
5. 若当前固件无法满足扫描期间的电话响应要求，限制扫描入口并明确可用性影响，不能把风险描述为已解决。
6. AT 命令行拒绝内嵌 CR/LF 和非法控制字节；提示模式的合法短信载荷独立校验。保留控制台正常调试用途，对高风险动作明确权限。

**验收**：CPMS/CMGF 等相关序列不交错；接听/挂断等待有测量记录；拒绝注入不改变原指令后继续执行；扫描不会因页面访问自动触发。

### 步骤 08：统一电话控制并整合上游

对应：A1、Q1、Q2。

1. 列出本地 SIP、来电窗口和上游电话、模块音频、Swift 应用的全部入口及职责。
2. 确定唯一的活动通话状态来源；网页、原生窗口、SIP 客户端均通过同一控制层发起操作，操作携带通话标识并可去重。
3. 每个活动通话只有一个音频生命周期管理者；不同媒体路径采用互斥选择，不能同时争用设备。SIP 媒体作为明确适配路径保留。
4. 对号码更新、接听、拒接、对端取消、超时和设备断开建立统一事件；同一通话只生成一份历史记录。
5. 在隔离分支分域整合，保留本地已验证行为；先装配及编译，再接入界面和历史。自动合并成功仍需语义检查。
6. 验证旧 API 的调用者并采用兼容适配；移除重复入口前完成调用迁移，不把 ES modules 改造夹入同一整合提交。

**验收**：一次拨号或接听只产生一次设备动作；原生和网页状态一致；没有重复音频会话、重复来电窗口或重复历史；整合前后的电话用例均通过。

### 步骤 09：完成来电体验、双向声音和音质验收

对应：功能报告 C03–C12、P05 及其他待完善项。

1. 以稳定通话 ID 统一来电去重键；号码晚到只更新现有窗口、通知状态和历史，不再次响铃或推送。
2. 统一铃声所有权：原生提醒可用时由原生播放，网页不重复播放；原生不可用时网页回退。静音作用范围在各入口保持一致。
3. 原生接听失败应显示错误并提供重试；再次操作前核对通话状态，避免失败反馈与后端实际成功不一致。
4. 验证无号码、晚到号码、主叫取消、拒接、连续来电和网页关闭；没有号码时不能编造来电身份。
5. 分段测量首声等待和媒体延时，检查音频准备、采样率转换、帧长、缓存积压、欠载和 AEC 路径；根据瓶颈逐项修改。
6. 耳机与扬声器分别比较回声、失真、音量、截断和断续；不能通过单向静音或过强门限换取表面无回声。
7. 外部 SIP 客户端的注册、呼入、呼出及双向媒体单独验收，不用本机通话通过替代。

**验收方法**：先按步骤 02 记录基线，再填写首声和往返延迟的测量方式、目标值及样本数，真实测试前固定口径。至少完成三组前后对照、一次不少于十分钟的通话及连续接听/挂断测试；这些是测试计划，不是已达到的性能承诺。音质需用户听感确认，统计不得隐藏失败样本。

### 步骤 10：补齐后台退出与任务恢复

对应：R3、R4、R9。

1. 建立应用根上下文，贯穿短信轮询、Bot、任务循环和通知工作协程；可取消等待替代不可中止的休眠。
2. 退出时停止接收新动作，取消后台操作，结束提醒及音频，等待工作协程，再释放设备；按依赖顺序实现并设置总退出期限。
3. 任务“立即执行”和周期执行共用并发控制，同一任务不重复执行。
4. 引入持久化执行实例和阶段：准备、执行中、成功、失败、结果不确定。关键执行意图保存失败时，不发起收费或重启动作。
5. 对“硬件已执行、结果未落盘”的窗口，恢复为结果不确定，禁止盲目补发短信或再次重启；提供查询与人工处理入口。
6. 不吞掉保存错误；日志、任务状态和 API 返回可见错误。兼容读取旧任务文件，新增格式保留迁移备份。

**验收**：模拟各阶段退出、断连和磁盘错误；不会承诺硬件动作恰好一次；后台可在约定期限内停止，停止后不继续发送或控制设备。

### 步骤 11：统一业务状态和异常数据处理

对应：R6、R7、R8；功能报告 F02/F03/F06 和 GNSS 待完善项。

1. 小区锁区分不支持、未知、锁定和未锁定，写命令成功不等于读回确认。
2. 网页、HTTP 与 MCP 使用同一 USSD 状态快照，覆盖 idle、活动、结束、失败和超时。
3. IMS 区分注册、未注册和未知；查询错误同时保留安全的原因，不据此否定通话能力。
4. GNSS 拒绝 NaN/Inf、无效经纬度和分钟范围；无定位与解析错误分别处理。
5. 明确偏好设置、模块实读状态和最后成功状态，避免旧缓存冒充当前设备状态。

**验收**：相同输入在各客户端得到一致状态；不支持、查询失败、坏数据和过期数据不会显示为确定正常。

### 步骤 12：固化构建、测试与平台支持

对应：D1、D2、D3、D4、Q3。

1. 通用解析移出 darwin+cgo 文件，补齐 stub；无 cgo 场景返回明确不支持，不伪装成硬件可用。
2. CI 保留普通测试，增加支持平台上的竞争测试和无 cgo 构建检查；需要 cgo/硬件的部分明确条件和跳过原因。
3. Intel、ARM64 分别记录构建、打包和运行验证；未做硬件回归的架构不能标记为完整支持。
4. 通过实际构建链接参数定位重复 `-lobjc` 来源，再消除冗余；不凭警告推定构建脚本是原因。
5. 测试覆盖前面步骤的真实故障边界，避免仅验证字段赋值或镜像实现。

**验收**：提交对应检查通过；跳过项、平台边界及已知失败可追踪。测试运行不隐式触发外部业务动作。

### 步骤 13：逐功能回归

以功能梳理报告的完整编号为检查表，不仅复测修复涉及的几个接口。

**验收**：可以定位并恢复上一可用版本；恢复后仍遵守任务防重发和凭证保护要求。
