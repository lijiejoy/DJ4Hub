# DJ 4G Hub 功能优化与逐项验证记录

日期：2026-11-07，Asia/Shanghai。范围：当前本地工作区及本机安装的开发版，包含此前尚未提交的功能。

## 1. 本轮结论

已完成一轮覆盖九个页面、服务管理、电话提醒、通知、任务、无线状态和异常输入的优化，并构建、安装到 `/Applications/DJ 4G Hub.app`。

自动测试、并发竞争检查、无 cgo 测试、Swift 服务生命周期测试、原生通话面板测试和网页检查通过。本机 27 个只读接口正常返回，HTTP/SIP 监听正常。

**这些结果不等于所有业务已经完成实机验收。** 本轮没有发起真实电话、短信、USSD 或外部测试推送，没有执行切卡、Profile 下载/删除、模块重启、锁小区、运营商扫描或 USB 模式切换。既有通知后台保持原配置，不能把后台连接当成本轮推送投递验收。

安装后的重要状态：麦克风权限为 `not_determined`。本地临时签名构建更新后，系统可能重新要求授权；下一次真实通话前需要用户允许麦克风。保持正式签名身份，是后续改善跨版本授权连续性的必要工作，当前不能承诺“永久免授权”。

本文更新 [早期功能梳理](2026-11-07-feature-audit.md) 的当前进展，并记录 [最终修复计划](2026-11-07-final-repair-plan.md) 的部分实施成果，不宣布整份计划全部完成。

## 2. 本轮已实施的优化

| 编号 | 原问题 | 本轮处理 | 验证 |
| --- | --- | --- | --- |

## 6. 下一阶段的明确优先级

| 优先级 | 工作 | 验收标准 |
| --- | --- | --- |
| P1 | 正式签名与麦克风授权连续性 | 使用同一可信签名身份构建升级；验证初次授权、重开、升级与隐私设置拒绝后的恢复 |
| P1 | 真实通话与音频专项 | 呼入/呼出、连续至少三次接听挂断、主叫取消、网页关闭、耳机/免提；测量点击接听到首声及端到端延迟，完成至少一次十分钟通话 |
| P1 | USB 生命周期与 AT 事务/优先级 | 并发打开、旧连接错误、物理热插拔、短信多命令事务、扫描期间来电；不能只依赖当前竞争检查 |
| P1 | 完整本地 API 认证 | 本地配对、会话、CSRF、原生客户端凭据一并接入；不能把无 Origin 当成可信身份 |
| P2 | 真实短信、USSD、任务和通知 | 在测试卡/明确测试目标下逐项完成发送、接收、回执、确认、重试和中断恢复 |
| P2 | eUICC、GNSS 与网络切换 | 补齐兼容 eUICC、有效测试 Profile、定位天线、可恢复网络环境后验收 |
| P2 | 正式交付与长期运行 | Intel/Apple Silicon 分别构建、签名公证、安装升级回滚、休眠唤醒、持续运行与外部 SIP 验收 |

已完成的后台取消没有加入所有工作协程的统一等待屏障；已有 USB 命令也未全部具备可抢占取消。任务采用“结果不确定则暂停”，不是硬件动作 exactly-once 保证；没有补齐断电场景的 fsync 持久化。

原生与网页铃声已经避免同时播放，但没有统一的跨端永久“静音来电”设置：原生持有铃声时隐藏网页的独立静音入口，网页仅在接管后提供自己的静音。更全面的静音行为仍需单独设计与验收。
