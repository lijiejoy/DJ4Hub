# DJ 4G Hub 功能梳理与逐项排查

日期：2026-11-07，Asia/Shanghai。对象：当前本地工作区，含未提交改动；不代表已发布版本的认证结果。

## 1. 结论

当前项目已实现设备管理、短信、实体 eUICC 管理、USB 网络诊断、无线信息、任务、通知和通话。主程序注册 **62 条 HTTP 方法/路由组合**，网页有 **9 个功能入口**；GNSS、多模块枚举和 MCP 分布在无线、任务页面及 API 中。

本次完成来电窗口与号码显示修复，并更新本机服务。原生构建下全部保留包的测试及竞态检查通过，25 个实机只读接口返回 HTTP 200。但普通实体 SIM、GNSS 无定位、固件不支持小区锁查询等情况，不能仅凭 HTTP 200 标记为业务验收通过。

**通话具备真实双向音频能力，仍处于实机优化阶段。** 用户在前序测试确认双方可听见声音；回声、音质与延迟仍需新版本的持续通话验收。新来电窗口完成了本机界面、号码更新与按钮验证，更新后真实手机呼入接听仍需再测。外部 SIP 客户端兼容性也需单独验收。

## 3. 来电窗口与未知号码修复

### 确认的原因

1. 用户截图是旧 AppleScript 系统提示框，其文字在窗口创建后不会更新。
2. 后台实际呼入记录已经有完整号码，因此不能把本次“未知号码”归因于用户隐藏主叫号码。
3. 第一声 `RING` 到达时号码为空，窗口立即创建；后续号码到达只修改 `Call.Number`，原先不发布更新快照。
4. USB 路径实测 `AT+CLIP?` 为 `+CLIP: 0,1`，主动号码上报关闭。
5. 原先产生响铃记录后停止来电轮询，减少了通过 `CLCC` 补查号码的机会。

## 5. 未修复问题与优先级

以下是排查结果，不代表已经修复。P1 优先处理稳定性或凭证保密，P2 为正确性、兼容性和体验问题。

### F01 / P1：打开无线页面会自动触发运营商长扫描

- 位置：`radio_handlers.go:listOperators`、`web/app.js:loadRadio/loadOperators`。
- GET 在缓存为空/过期时直接启动扫描，页面打开和轮询会调用该 GET。
- 长 AT 扫描可能占用共享 USB 命令通道，影响其他查询与呼叫控制；本轮未在真实模块重现扫描和来电并发。
- 建议：GET 只返回缓存/idle，POST 才扫描；通话期间限制扫描并提示忙状态。

### F02 / P2：锁定状态查询不支持，界面仍显示“未锁定”

- 位置：`web/app.js:loadCellLock`，约 1779 行。
- 实机返回 `supported=false`，页面只判断 `locked`，忽略支持标记和 note。
- 建议：显示“当前固件无法查询锁定状态”，分开未知/锁定/未锁定；写命令接受不代表读回确认。

### F03 / P2：MCP USSD 状态与网页不一致

- 位置：`mcp_handlers.go:mcpCallReadTool` 的 `ussd_status`。
- 顶层 state 固定取 `ussdStateForStatus(0)`，总是 ended；HTTP 空会话为 idle，活动会话应返回自身状态。
- 建议：提取共享快照，补齐各会话状态的一致性测试。

### F04 / P1：邮件异常可能导致空指针，完整超时约束不足

- 位置：`notify_handlers.go:sendEmail`，约 980–991 行。
- SSL 分支 `smtp.NewClient` 后不检查 err，继续使用并延迟关闭 client；欢迎报文失败时客户端可能为 nil。
- 非 SSL 的 `smtp.Dial` 和后续 SMTP 操作没有完整连接 deadline；STARTTLS 错误也被忽略。
- 建议：检查全部分支错误并清理连接、设置 deadline、严格处理 TLS；用本地模拟 SMTP 故障验证。本轮为代码确认，未执行异常服务器复现。

### F05 / P1：通知网络错误可能把凭证 URL 写入日志

- 位置：`notify_handlers.go:telegramBotLoop/telegramPollOnce` 及共享 HTTP 推送错误路径。
- 网络错误可能包含完整请求 URL，而 Bot 凭证在路径中；直接 `%v` 打印不能保证脱敏。
- 建议：统一过滤错误与配置 URL，只记录通道、主机、状态和安全原因，检查既有日志。报告不收录任何凭证值。

### F06 / P2：IMS 查询失败被表述为“IMS 未注册”

- 位置：`ussd_handlers.go:ussdIMS`、`web/app.js:loadUSSD`。
- 实机附带 `ims_error="modem did not report +QIMS"`，页面仅根据 false 显示未注册。
- 查询失败是状态未知，不能据此否定此前成功的通话；应区分注册/未注册/未知。

### F07 / P2：任务不能保证崩溃后的恰好一次执行

- 位置：`tasks_handlers.go:runDueTasks/runTask`。
- Running 只设在内存里，执行后才保存结果与下一次时间；业务成功而结果未落盘时崩溃，重启可能补跑。
- 建议：记录执行实例及阶段，对收费/重启动作制定恢复语义，不承诺“绝不重复”。

### F08 / P2：关闭 cgo 后主程序构建失败

- `CGO_ENABLED=0 go test ./...` 缺少 `usbAT.Description`、`atResponseIsError`、`atProbeSucceeded` 等。
- 部分通用解析仅定义于 darwin+cgo 文件；其余保留库包通过，生产原生构建不受影响。
- 建议：提取跨平台解析、补齐 stub；或明确限定主程序原生依赖和测试范围。

### 其他待完善

- GNSS 缺少完整经纬度范围、分钟范围和 NaN/Inf 校验；正常样本不覆盖坏数据。
- 原生窗口接听失败只记日志，缺少窗口内明确错误和重试操作。
- 原生与网页铃声可能同时播放；网页静音只控制网页声音。
- HTTP API 默认 loopback，但缺少统一认证/Origin 校验；修改监听地址不等于已支持远程管理。
- README/结构说明落后于新增能力；本轮补了报告入口与关键结构，完整产品文档仍需持续更新。
- ARM64 发布配置存在，但本轮只验证 Intel 原生构建，未验证双架构发行包。
