# 接通后声音等待优化记录

日期：2026-11-07。范围：本地 SIP/网页通话音频启动；真实通话的首声体验待用户复测。

更新：下文直接复用语音路由的方案已被替换。连续通话验证发现该方案会造成后续通话静音；
现在每通重新建立自有 DSP 路由，保留资源与独立 ADB 服务复用，准备实测约 2.2 秒。
详见 [连续通话与授权修复记录](2026-11-07-consecutive-call-fix.md)。下文数据仅为初版历史记录。

## 原因与修改

原实现虽然在拨号或响铃时就开始准备音频，但每次仍启动并关闭独立 ADB 服务、复制运行资源、重启模块侧语音路由，然后初始化电脑音频。实机测得完整准备需约 7.4 秒，快速接听可能发生在准备完成之前。

本次修改：

1. 服务启动后在后台预热模块侧语音路由，不打开电脑麦克风或扬声器。
2. 在通话桥生命周期内复用独立 ADB 服务，关闭通话桥或准备失败时清理。
3. 每次调用仍校验 USB 位置、脚本与资源哈希、进程归属及启动时间、校准和双向 PCM 运行状态。健康路由直接复用；检查失败走完整恢复，不盲目相信缓存。
4. 保留模块与电脑音频的可靠打开顺序，电脑音频仍在拨号/响铃阶段初始化，接通后才启动采集与播放。

曾尝试并行初始化两端，但在本机连续出现“多个模块音频设备”识别错误，已撤回该方案，没有纳入最终实现。

## 实测结果

环境沿用本机 Intel Mac 和 QDC507 模块。以下硬件测试未拨号、未保存音频。

| 项目 | 结果 |
| --- | --- |
| 修改前完整准备 | 7.359 秒 |
| 修改前阶段抽样 | 模块侧约 5.6 秒，电脑侧约 1.5–1.9 秒 |
| 新版后台模块预热 | 3.588 秒，服务启动后完成 |
| 预热后的第一通准备 | 1.797 秒；模块/USB 0.479 秒，电脑 1.284 秒 |
| 同进程下一通准备 | 1.720 秒；模块/USB 0.450 秒，电脑 1.209 秒 |
| 已准备电脑音频启动到回调 | 约 193 毫秒 |
| 接听前电脑音频计数 | 采集、播放均为 0 |

完整准备时间减少约四分之三，而且通常可在拨号或响铃阶段完成。约 193 毫秒只是已初始化音频单元启动到回调的测量，不能等同于手机接通到听见声音的总时间。

## 本机更新

已重新构建并替换本机服务，保留上一可执行文件备份。新进程正常运行，HTTP/SIP 与模块音频可用，空闲状态没有打开电脑音频。服务日志确认后台预热在 3.655 秒完成；安装文件与本轮构建产物的 SHA-256 一致。

## 复测重点

真实手机分别呼入与接听呼出，比较接通后首声等待；同时检查回声、声音中断、连续呼叫和挂断后的资源释放。服务刚启动尚未预热完成、模块拔插或路由故障恢复时，仍可能进入较慢的完整准备路径。

本次没有进行新的真实电话听感验收，不将自动测试或设备回调正常描述为端到端延迟已经达标。
